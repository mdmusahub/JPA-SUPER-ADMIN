# Using the console

Open `/admin` and sign in with the username and password you set. The sidebar lists every entity, grouped, with its record count; the dashboard shows the counts and the chart below. Open an entity to browse its records: search, sort, filter, hide columns, save a view, export, open a record, create, edit, duplicate or delete one, and delete many at once. Every list, form and page works without JavaScript; script only adds comfort (the `/` key, saved views, the upload progress bar). Light and dark themes follow your system until you choose. The sections below explain the parts that need a few words.

## The "Records created" chart

The dashboard shows how many records of each entity were created on each of the last 7, 30 or 90 days, as stacked bars (one colour per entity), with a legend that gives each entity's total and a closed "Daily counts" table that holds the same numbers as text. The range switch is three plain links (`?range=7`, `?range=30`, `?range=90`); the card needs no script and works with JavaScript off.

**Which entities are in the chart.** An entity is in the chart when it has a creation timestamp field: a field that is visible and not sensitive, of type `LocalDate`, `LocalDateTime`, `Instant`, `OffsetDateTime` or `ZonedDateTime`, and named one of the following (case is ignored, and so are `_` and `-`, so `created_at` and `CREATED-AT` match): `createdAt`, `createdDate`, `createdOn`, `creationDate`, `creationTime`, `createTime`, `createdDateTime`. When an entity has several, the first name in that list wins. A sensitive or hidden field is skipped, never read. `java.util.Date` and `java.sql.Timestamp` fields are not recognised. An entity with no such field is left out, and the card says which ones ("Not in the chart: ..."). When no entity has one, the card is hidden and one sentence under the stat cards says so.

**The range.** Only 7, 30 and 90 are accepted. A missing `range` is 30. Any other value (`45`, `abc`, a repeated parameter) is replaced by 30 and the card says "That range is not available, so the last 30 days are shown". The range is today and the days before it, so 30 means today and the 29 days before.

**What it costs a host.** One query per chart entity, built with the Criteria API, that selects only the creation column for the last 90 days (newest first, at most 50,000 rows) and counts the days in Java. No database function is used, so the same query runs on H2, PostgreSQL and MySQL. The answer is kept for 5 seconds: one dashboard load runs at most one such query per chart entity, a repeat, a change of range and the JSON endpoint inside those 5 seconds run none. An index on the creation column keeps the query cheap on a large table. Each entity is read in its own read-only transaction.

**The row cap.** If an entity has more than 50,000 records in the last 90 days, only the newest 50,000 are counted. The legend marks it "incomplete" and a note names the day up to which the counts are incomplete. A shorter range that lies inside the complete part is not marked.

**Time zone.** Days follow the `Clock` bean of the host application when it has one, otherwise the server's default time zone (set the JVM zone, `-Duser.timezone`, or define a `Clock` bean to change it). A `LocalDate` or `LocalDateTime` value is a calendar value and is counted on the day it holds; an `Instant`, `OffsetDateTime` or `ZonedDateTime` is counted on the day it falls on in that zone. Days are the server's, not the viewer's.

**A table that cannot be read.** The entity is shown as "unavailable" with a plain message, one log line (without a stack trace) is written per 5 seconds at most, and the rest of the dashboard and the other entities are unaffected.

**The JSON.** `GET {path}/api/stats?range=7|30|90` answers the same data as JSON: `range`, `entities` (`name`, `label`, `available`, `total`, `capped`), `days` (`date`, `counts` in the order of the entities) and `notes`. It needs the signed-in session (an anonymous request is sent to the sign-in page), answers GET only (a POST is refused), and holds no entity, no sensitive value and no hidden entity. It is for the console and is not a stable public API in v0.1.

**Limits.** A 7-day view reads the same 90-day window as a 90-day one. Counts are incomplete beyond 50,000 records in 90 days. A creation column that is not the moment of creation (imported rows) shows what it holds. An entity whose URL name is `api` cannot open its record with the id `stats`.

## CSV export

Every list has an **Export CSV** button in its header. It downloads the records the list is showing, as a UTF-8 CSV file, with the search, the filters and the sort of the page (not its page number or size: the file is every matching record, up to the cap). The button is a plain link, so it works without JavaScript.

**What is in the file**

- The **columns** are exactly the list's visible columns, in the list's order, under the same headers. A sensitive field (a name from `jpa.admin.sensitive-fields` or `@AdminSensitive`) is not in the file at all, not even as a header; nor is a hidden field, a collection, an embedded value or binary data. The value of a sensitive field is never read from the database for an export.
- **Dates and numbers** are written for machines: dates in ISO-8601 (`2026-03-09`, `2026-11-19T10:15:30`, an offset kept as stored, `2026-11-19T10:15:30Z` for an instant), never converted to another zone; numbers plain, with a decimal point, no thousands separators and no exponent (`1234.50`). **Booleans** are `true` and `false`; an **enum** is its constant name (`OUT_OF_STOCK`), not the list's wording; **text** is complete (not cut like the list's cells) and keeps its line breaks. An empty value is an empty cell.
- A **relation** is the related record's label, as the list shows it. A relation with no label (the target has no text field, or is hidden from the console) is exported as the plain id, without the `#` of the list. An **upload field** is exported as the address text that is stored in it, not the file.
- **Quoting** follows RFC 4180: a cell that holds a comma, a double quote, a carriage return or a line feed is wrapped in double quotes, and a double quote inside it is doubled. Rows end with `\r\n`. Control characters other than tab, carriage return and line feed are dropped.
- **Spreadsheet formulas (SEC-10).** A cell whose first character is `=`, `+`, `-`, `@`, a tab or a carriage return gets a single quote in front of it, so Excel, LibreOffice and Google Sheets show the text and do not run it. The rule has no exceptions, so a **negative number is exported as text** (`'-2.50`): a spreadsheet will not add it up until the quote is removed. The header cells follow the same rule.

**How big a file can be.** At most `min(jpa.admin.export-max-rows, 50000)` rows: 50,000 is a fixed ceiling and the property can only lower it. When more records match, the file holds the first rows in the list's order and the console says so in two ways: the response carries `X-Export-Truncated: true` and `X-Export-Row-Limit: <the cap>` (only when the file is cut), and the **list page itself** shows a notice, "Export is limited to the first 50,000 of 120,345 matching records. Narrow the search or the filters to export the rest.", whenever the total is above the cap. The file never has an extra row for a note, so it stays valid for every consumer. The notice is on the list page and not "after the download" because a download never replaces the page.

**The file name** is `<entity>-<yyyy-MM-dd>.csv` (for example `product-2026-11-19.csv`): the entity's address name and the date from the application's `Clock` (or the server's clock), ASCII only, nothing a visitor typed. The response is `text/csv;charset=UTF-8` with `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff` and `Cache-Control: no-store`. There is no byte order mark unless `jpa.admin.export-bom=true`; turn it on when Excel opens a file in the wrong character set (it breaks some other tools, which then see an invisible first character in the first header).

**Switches.** `jpa.admin.export-enabled=false` removes the button everywhere and makes every export address answer 403; `@AdminResource(exportable = false)` does the same for one entity. Both are enforced in the service, not only by hiding the button. A read-only entity can still be exported. An unknown or hidden entity is the console's 404, the same for both.

**Cost, for the host to know.** The export runs the list's own query in pages of 500 rows, each page in a read-only transaction of its own, so memory is bounded by one page and a slow download does not hold a database connection open. A file costs one count, the one small statement per filterable relation that the list also pays, and one statement per page: at the cap, about 100 statements. Paging with an offset gets slower the further it goes, and a search is a full scan as on the list (index advice is under Limitations). An export is a GET and changes nothing; it needs the signed-in admin like every console route.

**Limits.** The file follows the list's search and filters; it cannot export a different set. A record added or removed while a large file is being written can move a row from one page to the next (rows are not locked). If the database fails after the first rows were sent, the connection is cut, so a half file is never taken for a whole one. The Excel check (open a file with accents, a comma, a quote and a line break in Excel and in LibreOffice) is a manual item.

## Column visibility and saved views

Two ways to shape a list for yourself. Both keep their state in the address or in the browser and neither changes any record.

**Hiding columns.** The list header has a **Columns** panel next to **Filters**: one checkbox for each column that can be hidden, ticked when the column is hidden, and an **Apply columns** button. It is a plain form control (it works with JavaScript off) and travels with the search, the filters, the sort and the page size, and never the page number, so applying a choice shows the first page. The choice is in the address as a repeated parameter, `hide=<column>` (`/admin/product?hide=sku&hide=stock`), so Back, reload, a bookmark and a shared link all keep it. A column hidden this way is also **left out of the CSV export** (the file has exactly the columns the list shows) and its cells are neither selected nor joined by the list query.

- **What can be hidden:** a visible, non-sensitive column, the identifier too. A hidden (`@AdminHidden`) attribute is not a column, and a sensitive field is always shown as dots: its name in `hide` is ignored exactly like a name that does not exist, so hiding cannot be used to find out whether a name is sensitive. Every other name that is not a column key (unknown, empty, over 100 characters, repeated, or several joined with commas) is ignored one by one, silently, and at most 200 values are read.
- **At least one column stays.** A request that would hide every column that can be hidden is ignored as a whole and the page says so ("Every column was hidden, so all columns are shown. A list needs at least one column."). A masked column never counts as the one that stays.
- **When the identifier is hidden** the link to the record moves to the row's first visible, non-empty text or number cell, so a row still opens its record.
- **Sort, filters and search are conditions, not display.** A hidden column can still be sorted by, filtered on and searched. A hidden relation column that the list is sorted by keeps its join for the ordering only, and nothing of it is selected. The empty-state hint that names the columns a search looks in can name a hidden text column.
- **Cost, for the host to know.** A hidden column adds no select and, for a relation, no `LEFT JOIN`, so a page with hidden relation columns has fewer joins. The statement count is unchanged (a count, a page, and the small choices statement of each filterable relation: hiding a column does not remove a filter).

**Saved views.** The **Saved views** panel stores a name for a combination of search, filters, sort, page size and hidden columns, for one entity, **in this browser only** (`localStorage`, under `jpa-admin.views.<console path>.<entity>`). Nothing about a view is sent to or kept on the server.

- **Save** the list as it is now under a name of 1 to 60 characters (no control characters); the state saved is the one the server validated, never the raw address. Saving under an existing name (any letter case) replaces that view. **Apply** is a plain link to the list's address built from the view with every value percent-encoded, and it never carries a page number, so applying a view starts on page 1. **Rename** and **Delete** are in the same panel; delete asks first. A view is **shareable only as the URL it produces**: copy the address.
- A view is `{ name, q, filters, sort, dir, pageSize, hiddenColumns }`. At most **20** views per entity; a 21st is refused with a plain message and the old ones are kept.
- **What is dropped.** When a stored view is read, anything that does not fit this page is dropped without a notice: text that is not valid JSON or not a list, an item that is not an object, a name that is missing, longer than 60 characters or has control characters, a column or filter this entity does not have (so a view of a column that was renamed disappears), a page size that is not 10, 25, 50 or 100, a direction that is not `asc` or `desc`, a view that hides every column, a repeated name, and any view past the twentieth. A view never holds a sensitive column's name or any value of one.
- **Limits to know.** Views are only as good as the browser's storage: clearing the site's data removes them, a private window starts with none, and they are not synced between browsers or devices or shared between administrators (there is one administrator in v0.1). When storage is blocked or full the panel says so, saving is switched off, and everything else on the page works. The Saved views panel needs JavaScript (without it the panel says so; the Columns and Filters panels and the address still work). The "Clear search" link returns to the plain list address, which shows every column.

## The keyboard, the sidebar and the look

- **`/` focuses the search box** of a list (and the sidebar's entity search on a desktop page that has no list search). It is an enhancement that needs JavaScript: it never acts while you are typing in a field, with Ctrl, Alt or Meta held, or on a phone, and a small `/` key cap shows in the box only when the script runs. Without script, a **"Skip to search"** link at the very start of every list page (after "Skip to content") does the same and needs nothing. No other shortcut exists.
- **"Show all columns"** is a link in the Columns panel, there exactly when a column is hidden; it keeps the search, filters, sort and page size. **"Clear search"** (and "Clear search and filters") keeps the hidden columns and clears the search, the filters, the sort and the page size; the way back to every column is "Show all columns".
- **Tables are named in the plural** in the sidebar, on the dashboard and in headings (`Categories`, `Orders`); a host with an irregular plural says it with `@AdminResource(plural = "People")`.
- **A long table keeps its header in view** from a 900-pixel-wide window up: the table scrolls inside its own box and the header stays at the top of the box. On a phone the page scrolls and the table scrolls sideways only.
- **Messages stay until you leave the page.** They are not timed, so a slow reader or a screen reader never loses one.
- **Light and dark** follow the system until you choose; every page works in both.
