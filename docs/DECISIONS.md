| D-35 | **The security chain (2026-11-01; approved by the maintainer 2026-11-02, except the sign-out rule, replaced by D-39).** One `SecurityFilterChain` bean, `@Order(HIGHEST_PRECEDENCE)`, `securityMatcher({path}/**)` built from `BasePath`. Public: `{path}/login`, `{path}/assets/**`, `{path}/theme.css`; everything else needs the authority `ROLE_JPA_ADMIN` (checked as an authority, so a host's role-prefix setting cannot lock the admin out). Local authentication: a `ProviderManager` with one `DaoAuthenticationProvider` and **no parent**, handed to this chain only; the password is hashed with BCrypt once at startup; the user lookup returns a fresh copy each time (Spring erases the credentials of the principal it is given) and a never-matching stand-in for any other name (so no "user not found" path and no attempted name in the log, and equal work for every attempt); the name is matched exactly. **Nothing from Spring Security's extension points is a bean** (`UserDetailsService`, `AuthenticationManager`, `AuthenticationProvider`, `PasswordEncoder`, `RequestCache`, `SecurityContextRepository`, `CsrfTokenRepository`, handlers, entry point): a host's chains and Boot's auto-configuration pick up beans of those types; tests compare the bean sets with the console off and on. Three modes, one chain bean: a host with Spring Security (Boot's or its own `@EnableWebSecurity`) gets the chain added to its `FilterChainProxy`, and the auto-configuration is ordered after Boot's `ServletWebSecurityAutoConfiguration`, so Boot decides about its default chain first and a host that relies on it keeps it; a host without Spring Security gets `@EnableWebSecurity` imported by the console, only while no `springSecurityFilterChain` exists, and a `DelegatingFilterProxyRegistrationBean` for `{path}` and `{path}/*` only (REQUEST and ASYNC, order -100), so no other request meets Spring Security (no filter, no HTTP firewall, no generated user). The console backs off completely when Spring Security or Thymeleaf is missing. **Session and cookies:** nothing global is changed (SEC-8). Everything the console keeps in the shared HTTP session has its own name (`JPA_ADMIN_SECURITY_CONTEXT`, `JPA_ADMIN_CSRF_TOKEN`, `JPA_ADMIN_SAVED_REQUEST`), so a host user is not signed in to the console, the admin is not signed in to the host, and signing in or out of one does not overwrite, rotate or replay the other's state; signing out clears only the console's own state and ends the session only if nothing else is in it (D-39; the first version of this decision ended the whole session, which also ended a host login in the same browser, and was replaced).
