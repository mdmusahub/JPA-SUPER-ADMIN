# Annotations

Every annotation is optional and lives in the package `io.github.mdmusahub.jpaadmin.annotation`; the console works without any of them. Each is described below with its options and defaults. For examples, see [Customizing entities](customizing-entities.md). `@AdminHidden` and `@AdminSensitive` are read on the field or its getter.

- **`@AdminHidden`** — on an entity class or a field. On a class, the entity is removed from the console completely (no sidebar, no dashboard, not reachable by URL). On a field, the field is never shown, searched, sorted, filtered or exported. It cannot hide an entity's identifier (records are addressed by it); the console logs a warning and keeps the id if it is annotated.
- **`@AdminSensitive`** — on a field. The value is masked everywhere (SEC-1), whatever the field is called. It adds to `jpa.admin.sensitive-fields`.
- **`@AdminResource`** (on an entity class) — options `readOnly` (default `false`; the console only shows the records: no create, no edit, no delete), `creatable` (default `true`; `false` forbids creating and duplicating only), `updatable` (default `true`; `false` forbids editing only) and `deletable` (default `true`; `false` forbids deleting only). `creatable`, `updatable` and `deletable` are ignored when `readOnly`. Enforced in the service layer, not only by hiding a button (SEC-11): a forged request answers 403 for a visible entity and 404 for a hidden one. Inherited by subclasses. `exportable`. The other options that were considered (display name, group, icon, order, default sort, page size per entity) are **not yet** available.

- **`@AdminUpload`** (on a `String` field or its getter) — marks the field as the address of an uploaded file. Options: `storage` (default `"default"`), `folder` (default empty), `accept` (default `image/png`, `image/jpeg`, `image/gif`, `image/webp`, `application/pdf`; only those five can be recognised, so SVG, HTML and every other type stop startup), `maxSize` (default the storage's `max-size`, for example `"2MB"`; lowers the limit, never raises it). A field that is not a `String`, a storage that is not configured or a wrong folder, type or size stops startup with the field named. Status: supported: the upload input in the forms, the uploader, the image and file cells. See "File uploads".

- **`@AdminResource(plural)`** — the plural of the entity's name for headings, the breadcrumb, the search box, the empty state, the sidebar and the dashboard. Default empty: the console guesses by plain English rules (`Category` becomes `Categories`, `Box` becomes `Boxes`; `Person` would wrongly become `Persons`). At most 60 characters and no control character; anything else stops startup with a message that names the entity. `@AdminResource(plural = "People")`.
- **`@AdminBadge`** (on an enum or `String` field or its getter) — chooses the colour of the badge that shows a value in lists and on the detail page: `@AdminBadge({"PUBLISHED=green", "DRAFT=amber", "ARCHIVED=grey"})`. An entry is `VALUE=tone`; the tone is one of **`green`, `amber`, `red`, `grey`** (any letter case), and nothing else is accepted: a colour code, a style or any other word stops startup. On an enum field the value is the name of a constant and must exist; on a `String` field it is the text as stored (upper and lower case matter) and the field is shown as a badge with that text (still sortable and searched). A value the annotation does not list is **grey** (the host has taken charge of the colours); an enum without the annotation keeps the console's word list (`published`, `paid`, `active` green; `pending`, `draft`, `new` amber; `cancelled`, `failed`, `archived` red; the rest grey). A sensitive field is always masked, so the annotation does nothing there. Every wrong entry stops startup with one report that names the entity and field and the position of the entry and does not repeat what you wrote. The badge is a class name, never a style, so it follows the light and dark theme.
- **`@AdminLookup`** (on a to-one relation field or its getter) — names the property of the related entity that labels its records wherever the relation is shown: in the list and the detail page, in the relation filter and in the form's choice list. `@AdminLookup("serial")`. The property must be a visible, non-sensitive text (`String`) property of the related entity and not its identifier, else startup stops naming the relation field. A sensitive property is never a label, whatever the annotation says. When a related record has no value in that property the console shows the record's number (`#12`). Without the annotation the label is the first text property named `name`, `title`, `label`, `fullName`, `displayName`, `username`, `email` or `code`, else the first text property, else the number. A relation to an entity that is not in the console shows the number only.

**Not yet:** `@AdminField` (a label, help text, order or visibility per field) and the other `@AdminResource` options that were considered (display name, group, icon, order, default sort, a page size per entity). They are planned for a later version; a request for one of them is welcome as an issue.
